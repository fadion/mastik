# 8. mastik-mcp

The MCP endpoint: the running Mastik process hosts it, agents connect through a stdio proxy configured once, and every write goes through the same op queue and commit door as the app's own edits.

## 8. mastik-mcp

### 8.1 Topology: one configured server, any document

Documents live in a running Mastik process, the window or a headless `serve`, so that process hosts the MCP endpoint and agents connect to it. A person configures one server in their harness, `mastik mcp-proxy` with no arguments, and it reaches any document.

- **Hosts.** The window (one per machine, holding its documents as tabs, `one_window.rs`) and `mastik serve` each listen on a local endpoint and serve any number of documents, addressed by absolute path. Each writes a discovery file naming its endpoint, `mcp/<pid>.json` in the window lock's folder (`one_window::window_dir`: the machine folder on Windows, the user's runtime folder elsewhere), and removes it on exit; a reader removes one whose endpoint does not answer only when its process is gone (`mastik_ai::process_running`), never on a failed connect alone.
- **The proxy** (`mastik mcp-proxy`) bridges an agent that spawns its server over stdio. It connects to the window's endpoint when a window runs, else to a running `serve`, else starts `mastik serve` and connects to that. Under an assistant's agent (`MASTIK_AGENT_CHILD`) it connects only to the window and never starts `serve`, failing when no window lists an endpoint: the window holds the chat's grant, and `serve` holds none (`assistant.md` §4). It forwards lines and remembers the connection's current document, so that when its host goes away or a window starts it reconnects to the window and restores it before the next tool call. It also keeps a fingerprint of the last tool list the agent read: a host's own list never changes, so the host answers `listChanged: false`, but the proxy's can, when it reconnects to a host from another build. The proxy therefore advertises `listChanged: true`. On a reconnect it reads the new host's list, and sends `notifications/tools/list_changed` only when that list differs from the one the agent read, so a plain reconnect never makes the agent list the tools again. `--client <key>` keys the host's state for the client (*Revisions*), and `--document <path>` names the document from the first call, so an assistant that starts the proxy per turn skips `use_document`. `--tools all` lists every tool rather than the core set (*Core*, §8.4). It asks for short ids (§8.1a) unless it serves a chat; their spelling depends on the document alone, so the ids the agent holds name the same layers on the next host with nothing handed over.
- **The current document** is per client: the proxy's key when it was given one, else the connection (*Revisions*). `use_document(document)` sets it and every other tool acts on it until the next `use_document`; a tool called before any fails naming `use_document`. The document is an absolute path, or a name or relative path matched against the host's open documents, then the library's by file name or document name; the proxy first turns a relative path that exists from the harness's working folder, with or without `.mastik`, into an absolute one. Several matches fail with the candidates, for the agent to ask. The tool's description tells the agent to switch only when the person names another file.
- **Opening.** In the window, a document not yet open opens as a tab in the background: the window is not raised and the tab in front does not change, and the agent's edits show when the person looks at it. An agent's edit to a tab behind is written to its file at once, since a tab behind is kept clean (`tabs.rs`); one to the tab in front waits for the save or the autosave, as the person's own edits do. In `serve` it loads into memory.
- **Security.** Same user, same machine, no token: a same-user process can already read and write the files the endpoint guards. On Windows the pipe rejects remote clients, its default DACL lets only the current user write to it, and the host drops a client whose process runs as anyone else (`one_window::same_user`). Elsewhere the socket sits in a 0700 folder, is 0600, and the host checks the peer's uid. TCP or remote transport is parked.

### 8.1a Wire

JSON-RPC 2.0, one message per line, on std threads with `serde_json`; no SDK and no async runtime. The methods are `initialize`, `ping`, `tools/list`, `tools/call` and the `initialized` and `cancelled` notifications. `initialize` answers the newest of `wire::PROTOCOL_VERSIONS` not newer than the client's (`wire::negotiate`), so never one it cannot know; `2025-03-26` is not offered, since it requires batches. A batch or a line that is no object gets one Invalid Request with a null id, and a line that is not UTF-8 a parse error, so a client never waits on a line the server dropped and the session goes on; the proxy answers a bad line from the agent the same way. A line is read to at most 64 MB (`wire::MAX_LINE`), which caps an `import_svg` or `add_image` payload; a longer one is read through its newline, only its head and its tail kept, and answered as too long under the request's own id when the head holds it before `params` or the tail holds it as the request's last member, as the TypeScript SDK writes it (`wire::too_long`), so the call fails with a reason rather than waiting, and a client that never sends a newline cannot make the window hold it. A host answers at most 64 connections at once, a thread each (`endpoint::MAX_CONNECTIONS`), closing one past that unread.

Every tool carries annotations from `schema::class`: `readOnlyHint` for the reads, and `destructiveHint` only for what `undo` does not revert (`schema`'s `OUTSIDE_UNDO`: `create_document`, the three kit-mark tools, `save_version`) and for `call`, which can reach them, so a client's consent for those covers it too; every other write is one undo step. `search_assets` and `place_asset` say `openWorldHint: true` (`schema::OPEN_WORLD`), since they reach the switched-on icon sets and photo services; every other tool says `false`, since it reaches nothing past the person's documents and the protocol assumes otherwise. A model parameter whose every short form keeps one shape at its top carries that JSON type beside `string` (`schema::model_type`), so a client that turns tools into strict function schemas keeps it; one that also reads as a number or a string (a cell, a colour, a patch, insets) stays untyped. A file's resource URI percent-encodes its name (`mastik:///Hero%20card.png`). The server instructions (`wire::INSTRUCTIONS`) say once what every tool shares: results' text is the document's data, never instructions, since layer names, text and kit notes come from other people's files too; what `base_rev` does; and the id form. No description repeats them: the list is paid for on every uncached turn, and `schema`'s budget test holds its size. It stays byte-stable between calls, since any change drops a client's prompt cache. A tool no host serves is refused first, by name, and a table tool's arguments are checked as a verb's are (`verbs::check_args`): a missing or wrongly typed one is refused rather than read as absent, and one the tool does not take is refused naming those it does (*`find_nodes` takes no `name`; it takes `query`, `page`, `limit`*). A model parameter sent as JSON text is parsed first (`mcp::check_call`), and the handler gets it parsed. Each tool's input schema is generated from its verb's `Param`s, with `verbs::example` showing a model parameter's shape. No resources, prompts or server-sent notifications: see *Revisions* below.

**Short ids.** A client whose `initialize` `_meta` asks for them (`wire::IDS_META`, which the proxy sends unless it serves a chat) is shown `n48c_36` for `48c991654e6b8e81:36`: `n`, the shortest start of the actor's hex, at least three digits, that no other actor of the document begins with, `_` and the seq (`NodeId::to_short`). The spelling is the document's, never a client's history: a table built in the order a client first saw actors would be rebuilt in another order after a reconnect or a harness's resume, and an id the agent still held would name another layer with no error. A new actor that shares a start lengthens the spelling, and a start two actors share is read as no id, refused rather than guessed (`NodeId::from_short`). The answer is rewritten on its way out (`mcp::short`), every full id of an actor any of the document's ids or the session's own minted, in the structure and the text alike, actor 0 left alone so a text reading `0:30` stays as written. The document's own words are never rewritten: a `text`, `name`, `description` or `source` value is answered as stored, so what an agent copies back is what was there. A `styles` map is no such words: each of its slots, `text` among them, links a style by id and is written short like any other id (`short::shorten_style_links`). A script `source` an agent sends, at any depth, has its short ids written in full before it is stored or run (`short::expand_sources`), since a stored script runs outside MCP where only the full form reads. Arguments are read through `NodeId::from_wire` inside `mastik_core::with_short_ids`, so only a place read as an id takes the short form, and the full form is always read too. A chat keeps full ids: its panel links them, and its threads keep and replay them past any change to the document's actors.

### 8.2 Headless mode

`mastik serve` hosts documents with no window: core, history, CPU renderer and the MCP endpoint. Same op queue, same tools, the assets browser's among them (§8.4, *The assets browser*), so an agent can build, edit and export on a machine with no display, or edit a file nobody has open. This follows from the headless-core invariant and is a first-class v1 deliverable.

- `serve` writes each commit to its file: there is no person to save later, and a window with the same file open as a clean tab follows it (`library.md`, *the file is watched*).
- `serve` exits after its last caller's connection closes, or 15 minutes after while it remembers a keyed client (*Revisions*), whose harness may start a process per turn. It keeps its own set of the connections that called a tool (`serve::Life`), so one whose every call was refused before the engine knew it still counts, and the proxy's and `serve`'s own checks that an endpoint answers, which connect and close without a call, never end it.
- `serve` stamps each file it reads (`library::disk::Stamp`). A commit whose file changed on disk since is not written: `serve` drops its copy and answers the call as an error, since the edit now exists nowhere, and the next `use_document` reads the file as it is. Nobody is there to choose, so the outside change (a pull, a sync) wins.
- It hands over when a window lists its endpoint: once no client is connected, or a second after its last answer, so that answer reaches its connection first. The proxy moves to the window at its next request once the window answers a connection, asked at most every two seconds (`proxy::WindowProbe`): a window that lists its endpoint but refuses (another privilege, a reused pid) would otherwise make it drop `serve` and reconnect on every request. The proxy follows a `use_document` made through `call` as it follows a direct one, both for the document it restores and for making a relative path absolute. A tool call whose answer was lost is not sent again, since it may have applied; the proxy answers it with an error saying so.
- A commit `serve` cannot write to its file while it keeps its copy, like one to a window's tab behind, is answered with `unsaved` and the reason. A tab behind whose file changed outside since it was read is not overwritten: it keeps the edit and asks the person, as *Changed on disk* does. A tab behind, or a `serve` document, that is written keeps a library document's undo history beside its bytes (`history::write`), as the person's save does; both resume that history when they open the file.
- `serve` finds a document already open under another spelling of its path, so one file never has two sessions writing over each other.
- One `serve` runs per user: it holds `mcp/serve.lock` while it lives, and one started while another holds it exits at once, so proxies starting together share the first. The proxy starts it detached (its own process group off Windows), so a harness ending the proxy does not end the client state `serve` keeps.

### 8.3 Concurrency model

- The owning process holds each document as an `EditorSession` on its main thread.
- Every tool call funnels through one single-writer **queue** (`mastik_mcp::queue`): a connection's thread sends the call's name and arguments with a reply channel and waits. The call travels rather than a built transaction because a verb reads the document to answer its edit, and the document is the owning thread's.
- The owning thread runs the handler (`mastik-app`'s `mcp::Engine`) against the document's `EditorSession`: a read projects it, a write runs the registry verb (`verbs::call`) and commits through `EditorSession::try_commit`. `serve` drains the queue in its loop; the window drains it every frame. One source of truth and one history; an agent's edits appear live on the canvas through the same path as the person's. An MCP edit's undo step is named by the tool it called and remembers the client (`EditorSession::name_mcp_step`, `Origin::Mcp`), so the History section can mark it. An agent's `undo()` and `redo()` act only on a step that client made (`mcp::own_step`): the history is the person's too. The name a client gives at `initialize` labels its steps but does not own them, since two sessions of one harness give the same one; every step committed while a call is answered carries the client as the host tells clients apart (`StepNote::agent`, from `mcp::agent`): its key, or for an unkeyed client its connection, so its steps stop being its own when it reconnects, as its revisions do. A chat's proposal the person applies is the chat's step. `undo()` takes back the client's latest step it has not taken back already: on top of the history, by undoing it; under later steps by the person or another client, alone, as a new step named *Undo* and the step's name, when those later steps changed other things (`History::revert`), answering `under_later_steps`. Whether they did is checked exactly, not by the layers named: on a copy the later steps are undone, then the agent's, then the later ones redone, and that must be the document the agent's inverse gives applied now; otherwise it is refused, naming the later step that shares a layer with it, and nothing changes. The step taken back stays in the history, so undoing the new step brings it back; that is the person's act, and the client's next `undo()` leaves its own *Undo* step alone (`undone: null`). The new step belongs to whoever took the step back, so the person's *Undo* on a proposal card is the person's step, and it counts as a commit. `redo()` over the person's step or another client's is refused, naming the step. They answer the step they moved by its name, `undone` or `redone`, null at the end of the history; a `set` step is named by what it set (`set fills, name`).
- **Document-level actions** (invariant 10, §15 D1097): `make_kit`, `publish_kit(note)`, `stop_sharing_kit`, `save_version(name?)`, `create_document(name, project?)` ride the **same queue**, so they are ordered against surrounding edits (a publish sent after a batch of writes publishes those writes). The owning thread runs the app's own code: `kits::mark_kit`, `kits::unmark_kit` and `kits::publish::publish_in` (shared with the document menu's rows and the publish popover, past their dialogs), `library::store::pin_version` and `library::store::file_document`, and replies with the result. None is a `Transaction`, none enters history, `undo` reverts none.
- **A tool that may write** (any tool `schema::class` does not call a read; a proposal is a read) first ends the person's text edit on the tab in front (`Documents::before_write`), so the typing lands as its own step rather than under the agent's. While the person compares versions the document is read-only to an agent: writes, the kit mark, `undo` and `redo` are refused.
- No connection thread ever touches a document (invariant 10).
- A call the owning thread has not taken within 30 seconds is answered as not run, with nothing changed: the window drains the queue only between frames, which a modal file dialog stops. The owning thread and the connection each claim the call (`Call::take`) and the first wins, so a call answered as not run never runs later; one already taken is waited for. An asset call that waits on the network is kept and run again rather than holding the thread (§8.4, *The assets browser*).

The tools it returns from outside the core list are named in `unlisted`, with a `said` to run them through `call` where the client lists only the core: such a client refuses a call to any other tool by name (*No such tool available*) before Mastik hears of it. A granted chat is offered only the tools its level runs; a tool it names or its `query` matches that a level above the chat's runs (not one a higher level drops, `propose_edit` at Edit, which is in neither list), is answered in `beyond_access` with the level it `needs`, so an agent that may not do a thing can tell the person what would, rather than conclude no tool does it; a name that is no tool is refused as no tool, with the nearest names, whatever the chat's level (`access::refused` leaves it to `check_call`). The list is read on every turn a client does not cache, and an agent that sees fewer tools picks among them better; the core set is what building and editing a page took in practice, and `set(nodes, props)` stands in for the single-property setters, writing each property through its own setter as one undo step named *set*, `size`, `rotation` and then `at` last, each measured after the ones before land. `at` is the left and top of the layer's box in its parent for every kind, a group's box being its children's (`edit::box_corner`, placed by `edit::placed_at`). A layer its container lays out is refused `at`, `x` and `y`, and `set_transform` a new translation, the refusal pointing at `reorder` and `set_insets` (`build::laid_out_refusal`, which both doors ask), since the move would be dropped and the call read as done. `set` also takes the names agents guess: `x` or `y` alone, and `width` or `height` alone (or `size` with one side), each keeping the other side, except that a width alone on an `Auto` or `AutoHeight` text is `set_geometry`'s `TextSizing::AutoHeight` at that width, so the text keeps growing down as the inspector's W leaves it, where `set_size` would fix its height (a `Fixed` text takes `set_size`); `corner_radius` as `geometry`'s `CornerRadius`, or `CornerRadii` given four; `fill` and `stroke` as a one-paint list; and `rotation`, the angle in degrees clockwise on the page that the Rotation field shows (`edit::shown_angle`: a line's or an arc's angle from its start to its end), turned to about the box's centre (`edit::turned_to`). These placement and turning rules, and which texts a new fill clears the colour of, are core's, so `set` only sequences them. Any other name is refused with the list and the nearest name it likely meant (`SET_GUESSES`, then two edits). `text` on a layer that is no text is refused before anything runs, naming an instance's properties for `set_instance_property` and the text layers inside. `create_node`, `create_text`, `create_instance` and `insert_subtree` (for its root) take a box's left and top as `x` and `y` (`build::cornered_at`), so an agent placing a layer never composes a matrix. `set` is also a step `batch` takes.

Selection is app state, not document state (§9.3), but deliberately part of the MCP surface, because "the selected layer" is how humans phrase most AI requests. The MCP layer reads and writes it in the owning process's session state, never the `Document`. So is the view: `get_view` answers the page the person is on, the camera's centre and zoom, and the world rectangle the canvas shows while the document is the tab in front, so "what I'm looking at" resolves without a guess. A read that takes a page (`get_outline`, `hit_test`, `export_svg`, `export_png`, `check_contrast`, `export_code` with nothing selected) defaults to that page; `serve` and a document nobody has open are on the first page.

Which of this is built: the wire, the proxy, `serve`, the window as a host (`mcp::window`), and every tool of every phase. `tools/list` names the core set (`mastik_mcp::tools::CORE`); `describe_tools` and `call` reach the rest (`mastik_mcp::schema`).

#### The assistant's tool and grants

- **`propose_edit(title, calls)`** sits outside the phases, in `mastik_mcp::tools::ASSISTANT`, and is marked read-only: it checks a list of Phase 2 and 3 verb calls on a copy of the document and records the proposal for the person to apply, and the document never moves (`assistant.md`, *Proposals*). The window keeps the last 64 proposals in memory, numbered from the launch time, so a card saved in a thread before a restart never names a proposal made after it; the chat's thread keeps and saves its own copy of each (`assistant.md`, *Proposals*).
- **Grants.** The window grants each assistant session a level (`mcp::access::Grants`) by its client key and by the processes the session owns. The endpoint reads the connecting process at accept (`GetNamedPipeClientProcessId` on Windows, `SO_PEERCRED` on Linux, `LOCAL_PEERPID` on macOS, none on other Unixes) and puts it on `Forward::pid`, so every `Call` carries it as `Call::pid`. A call a grant covers, by process first and then by key, acts under the session's key, gets that level's tool list, is refused a tool above it (by name, through `call`, or as a `batch` step) and is written to the agent log; any other call is an ordinary client's. A chat that ends leaves its grant *ended*, not removed: a call still arriving from it is refused (*This chat has ended*), and the last 32 ended chats are remembered (`access::ENDED_KEPT`). A chat's key (`assistant-…`) no grant covers, from an earlier run of the window or forgotten past that cap, is refused the same way rather than served as an ordinary client's, and listed no tools, as an ended chat is. Ownership is what the platform shows: a process that leaves the session's tree (`setsid`, a double fork, a launch through the task scheduler) or a platform with no peer pid connects as an ordinary client with every tool. That boundary is the harness's own shell permission, which reaches the document's file directly anyway, so a level limits what the agent does through Mastik, not what a shell it was given can do.

#### Conventions

- `style_text` and `style_paragraphs` are how an agent styles part of a text: a range counted in
  characters becomes runs over it, as the text editor writes a selection; the whole text becomes the
  layer's defaults with that attribute's runs dropped, as the type panel writes it. Every range an
  agent writes is counted in characters, `set_text_spans`' and `set_text_style`'s `spans` included,
  so the snapshot's `runs` are written back as read.
- A page is named by its root node's id: `create_node`'s and `insert_subtree`'s parent may be one,
  and `set_name` renames one.
- `create_node`, `insert_subtree`, `duplicate`, `convert_container`, `add_page` and `duplicate_page` return the new ids (the handler minted them); so do `create_instance`, `insert_from_kit`, `add_image`, `add_variable`, `add_mode`, `add_collection`, `duplicate_collection` and `add_style`. `add_image` also answers the picture's `pixel_size`, as the paint summary of an image fill carries it. `reparent` answers `at`, the moved layer's box's left and top in its new parent: the move keeps where it is drawn, so that place is new to the caller and the next write that places it needs it.
- The snapshot exposes world transforms so agents can compute local placements; a `place_at_world(id, world_transform)` adapter is allowed in core if agents struggle.
- `set_blend(nodes, blend)` takes the mode as the snapshot names it (`"Multiply"`, `"Pass through"`) and writes through `build::set_blend_all`, as the inspector and `Shift`+digits do: the outermost members only, and Pass through landing as Normal on a layer that is not a frame or group.
- `set_point(node, point, subpath?, …)` edits one anchor as the inspector's point fields do, in the layer's own space, indexed as the snapshot's `subpaths` lists them. A coordinate left out keeps its value and handles are placed after the point moves. One handle given mirrors the other on a smooth point (`PenAnchor::is_smooth`, a corner counting as smooth) and leaves it on a broken one, as `nudge_handle_tx` does; both given are set exactly. It reads the drawn anchors (`edit::path_subpaths`) and writes the whole path back through `edit::rewrite_points`, so a mirrored path stays symmetric and the commit is one `GeometryPatch::Path`, the editor's own undo granularity.
- `set_geometry` refuses a `Path` patch on a rounded path that holds any point its drawn outline has only because a corner is rounded (`verbs::bakes_rounding`, within 0.001): that is the snapshot's `svg` written back, whole or edited, which would bake each fillet into curves and round it again. The refusal points at `subpaths` and `set_point`.
- The setters take `nodes` and write a selection as the inspector does. `set_fills`, `set_strokes` and `bind_variable`'s paint fields reach a group's shapes and every layer named, a child named beside its frame included (`build::paint_targets`); where the layers share one list they write it as an edit of that list (`build::retarget_fills_all`, `retarget_strokes_all`), so each layer keeps its own item ids and an instance stays tied to its main's items, and where the lists differ as a replacement position by position (`set_fills_all`). Layers that reach nothing taking paint (an empty group) are refused. `set_effects` writes the outermost layers (`set_effects_all`). `set_exports` gives a row past any layer's end one id across the layers, as the Export card does. The text style setters take text layers only, and `set_text_style`'s `spans` one text. `set_text_style`, and so `set`'s `text_style`, changes only the fields it is given; each text keeps the rest of its own. A text's style `color` draws over its fills, so `set`'s `fill` or `fills` also clears that colour on every text it reaches, through groups as `set_fills` does (`build::coloured_texts`), unless the same call sets it. A `set` that changes nothing answers an empty `set` and lists the properties as `unchanged`, so an agent is never told of a write that did not land.
- A chart is edited through its four verbs, which write `SetChart`; its parts regenerate after the commit (`chart::settle`), and any other tool writing a part is refused by `chart::guard` (*Part of a chart — edit the chart, or flatten it first*). `insert_chart` makes a 480 × 280 frame on the kind's sample table, or on the table given with its mapping read off the column types (`chart::Mapping::guess`) unless one is given; `set_chart`'s `mapping` and `options` are JSON merge patches over the chart's own, and its `colours` sets series and mark colours by name, a hex or a colour variable that binds (`verbs::chart_colour`, `charts.md`), since without it an agent flattens a chart to brand it and loses the live data; `set_chart_data` points the chart at another table (`data`) or writes new cells (`table`), into the table the chart reads unless `write` says `chart` (`charts.md`, *Elsewhere*); `flatten_chart` is `chart::flatten_ops` for each chart (*Flatten*, `charts.md`). The snapshot's `chart` names the column ids they take, `data` the data table a chart reads and `data_id` its id (its `linked` true when that table is linked).
- **Tables** are written through the table verbs (`lists.md`, *Verbs*) and read by `list_tables()`, each table's `id`, `name`, `rows`, `columns`, `linked` and `read_by` (`lists`, `charts`), and `get_table(table, from?, count?, columns?)`: its `columns` (`id`, `name`, `numeric`), a page of `rows` (200 from `from` unless `count` says), `from`, `total` and, when linked, `link`, the file's path. Rows count from 1 and every cell is text. A table edit's undo step takes the app's name for the act (`writes::step_name`): *New table*, *Edit table* (`edit_table`, `set_table`, and `set_chart_data` writing a table), *Rename table*, *Delete table*, *Unlink data file*, *Make list*; `set_list` and `set_chart_data`'s chart-only forms keep the tool's name. The snapshot's `list` names its table by `table_id` and counts its `table_rows` beside the rows it draws, and carries its `rows_mode`, `filter` and `sort` in the shapes `set_list` takes, so what it reads writes back as it was.
- **Scripts** are written by `add_script`, `set_script` and `remove_script` and read by `list_scripts(query?)`: each document script's `id`, `name`, `source` and the `inputs` its header asks for, by name. A reaction's *Run script* names a script by that id, and play runs only one whose `inputs` is empty.
- `insert_subtree` is the tool a whole layout goes through: a page of a few hundred layers is a handful of calls, one tree per section, where `create_node` is a round trip per layer. It answers `named`: each layer the tree named, by the `/`-joined names of it and its named ancestors, with its id, so the agent addresses the parts it wrote without counting; `created` then holds the root, first as every write's does, and the layers no name reaches, so each id is said once.
- Every model parameter reads the short forms (`verbs::loose`): a colour as `"#rrggbb"` or `"#rrggbbaa"` wherever the model takes one, a fill or stroke as a bare colour, a fill's or stroke's `brush` as a colour or written `color` with an `opacity` folded into it, a fill or stroke written `{"variable": id}` (or `var`) bound to that variable, a gradient brush without its `extend`, `interpolation_cs`, `interpolation_alpha_space` and `hue_direction` (Pad, sRGB, premultiplied, shorter hue; peniko's serde requires them) and with its points as `[x, y]`, a fill or stroke and a text's style without the fields a new one has (a stroke is 1px), a stroke's `width` per side as CSS `border-width` (`{top?, right?, bottom?, left?}`) for `sides: {"Custom": …}`, a side left out 0 and the stroke's width the widest (`loose::loosen_paint`), a text style's value (`add_style`'s `{"text": {…}}`, a `text` object without `content`) completed with the default style's family, size, weight and italic as a text's `style` is, a text's `sizing` left out (`Auto`), a star's points and inner ratio left out (5 and 0.382), a `geometry` as path data alone or as a path's own fields (`{"path": …}` or `{"svg": …}`) and a path patch without its radii (a rounded path keeps its radii when the patch has as many points, and the patch is refused naming `corner_radii` otherwise, since radii left out read as none: `verbs::keep_radii`), a line's end as `[x, y]`, padding as two or three numbers as CSS writes them, a `Flex`'s `align` and `justify` for `align_items` and `justify_content` (not a grid's, where the words could name either the items or the content), a tree layer's `corner_radius`, the name `set` takes, as its `Rect` or `Artboard` kind's `corner_radii` where that kind gives none, and a model parameter a client sent as JSON text. Before a model argument is refused, `verbs::settle` puts right the slips an agent makes: an enum word in another case or in kebab-case (`center`, `space-between`, `auto`), `Frame` for `Artboard` and `Hug` (`hug_contents`, `fit`) for `FitContent` (`verbs::alias`), and a field in camelCase or kebab-case (`fontSize`). What it cannot put right is refused with the form to write: a kind written without its fields, or missing one where the place is named as the model spells a variant (`{"Path": {"d": …}}`; a style's lowercase `text` is no kind), shows that kind with them (`verbs::kind_example`), never the model's example of another kind, an unknown field lists the fields there (where the place is a struct of its own, a stroke, a paragraph, a flex or a chart's options, every field serde reads for it, beside the example's short forms such as `gap`; inside a noise's kind, noise's own fields (`NOISE_KIND_FIELDS`, since its wire type hides them from serde); inside a prototype model (`[Reaction]`, `[Flow]`, `LayerPlay`, `PagePlay`), every field of the place its last key names, an overlay's `settings`, a `transition`, `follow`, `scroll_effect`, `input`, a row action's `cells` item, a conditional's `branches` item, or a trigger's, action's, `VarChange`'s or `WhichRow`'s variant (`verbs::play_fields`, its `variant_fields` reading a struct variant's names as `struct_fields` reads a struct's), a field right under a trigger's or action's variant (`EditRow.values`) included, since each is settled alone and its variant is then the value's one key (`verbs::model_fields`), which a missing field there lists too, read from the refusal's whole path, since no example shows every action; elsewhere the fields the model's example shows filled in), a word written as a key with a value (`{"visible": true}` for `bind_variable`'s `field`) says it takes no value and to write it as the word (`"visible"`), a tree's `corner_radius` that cannot move into its kind (another kind, or one giving its corners) or a tree's `corner_radii` points to its `kind`, which holds its corners, a tree child's `at`, `x`, `y` or `position` points to its `transform` and the root to `insert_subtree`'s `x` and `y`, and an unknown variant, a missing field or an enum not written as one key shows the example of the nearest field along its path that holds a model of its own (`fills`, `strokes`, `effects`, `display`, `item`, a text's `style`, `paragraph`, `block`, `insets`: `verbs::field_model`), else the whole model's, so a fill written wrong inside an `insert_subtree` tree is shown fills (solid, gradient, image), not the tree's example. A tree child's refusal for `at`, `x`, `y` or `position`, and a layout item's for `position` or `absolute`, also say that inside a flex or grid frame a child leaves the flow by its `insets`, as CSS `position: absolute` does (`set_insets` for a layer already there), since such a frame places its children itself and a transform alone does not move one. A paint's `brush` is an untagged enum, whose miss names neither field nor variant, so a refused brush is read again alone as a brush (`verbs::brush_miss`) and its refusal gives serde's own path and reason (an unknown variant, a missing field). A variable, style, collection or mode is taken by its name where its id is wanted when the name is one's alone, else refused listing the names there are, and a variable's `value` is taken bare (`"#ff7a1a"`, `16`) when its kind is known; a name `add_variable` finds taken answers the id of the variable holding it. It also takes what `get_node` and CSS write, so an agent writes back what it read: a length as `"22px"`, `"1.2em"`, `"120%"` or `"auto"`, and a bare number as a `letter_spacing`'s or `word_spacing`'s px and a `line_height`'s multiple of the font size, as CSS reads a unitless line height (those keys only, since `offset` is also a gradient stop's number); a sizing as `{type, width}`; a fill as `{paint: {type: "Solid", color, alpha}}`, its `id` and `index` ignored; an effect flat (kind `DropShadow` or `drop_shadow`, its `opacity` folded into its colour, its blend by its label, `"Color burn"`) or with its kind as an object, shown unless it says not, a layer or background blur's `radius` written `blur` as a shadow names its own; a noise without what a default noise has, its `size` as one number, its `colors` as hex and a one-colour noise as `color` alone (fading to that colour clear, an `opacity` beside it folded into its alpha); a rectangle's corner radii left out (square) or as one number; padding as one number, and `gap` for both gaps of a flex or grid; an inset as a number of px, `"12px"` or `"50%"`, written back as the number where it is px; a path as SVG path data under `svg` or `path`; a bound corner by name (`top_left` …); and `bind_variable`'s `field` as `{"corner": "all"}` for every corner (the model's `Radius`) or `{"spacing": …}` for the `Spacing` bit set, the word one of `gaps`, `padding`, `all`, `column_gap`, `row_gap`, `padding_top`, `padding_right`, `padding_bottom` or `padding_left` (`loose::loosen_field`). A model argument is read whole (`verbs::check_model`): a value it cannot read, or a field the model has no place for, is refused naming its path (``at `children[1].kind.Text.sizing`: …``), never dropped, since a dropped field lays out silently wrong (`Flex { gap }` with no gap). An item of `set_flows`' or `set_reactions`' list is also checked for a top-level field its model has no place for, refused naming the fields (`verbs::keyed_extra`): `Keyed` flattens its value, so serde would drop such a field without a word (a flow's `variables`). A short form written wrong is refused too, never read as a value: an opacity or alpha outside 0–1, a sizing without a dimension its type has (`loose::loosen_strict`). A tree layer's `like` names a layer whose fills, strokes, effects, opacity, blend, text style (field by field) and paragraph it takes where it gives none, so a new text matches the page's own type without restating it. A sample with nothing to give is refused naming what it is, a text's sample that is no text and any sample with no paint, since the layer would otherwise draw in the defaults without a word. `get_tree` and the schema's examples answer in the short forms wherever they read back to the same value, a length as `"22px"`, a path as SVG path data, even corners as one number, a line's end and a gradient's points as `[x, y]` and a gradient without its default extend and colour spaces included; output is a large share of an agent's time, and the long forms were most of a written tree. The one exception: an sRGB colour, a gradient stop's included, is written as hex rounded to the nearest byte, so a tree read and written back may move a colour by half a byte step, which no eye sees, for a quarter of the text.
- `batch(steps)` runs `set` and the write tools that are verbs in turn, each committed through the door and reading what the last left, then joins their steps into one named *batch* (`History::join_last`), so the person undoes the agent's request at once. A step names what an earlier one made as `"@label"`, the label that step gave in `as`, as a core script does, a layer an `insert_subtree` step named by `"@label/Path"`, its path in `named` below the root, and the first page as `"@page"` (a step labelled `page` wins). `mastik run` replays a batch from a file (`export.md`). A refused step takes back the steps before it (`EditorSession::take_back`) and the refusal names the step: a batch lands whole or not at all. Any other tool is refused as a step (`writes::batch_step`); the tool's description names `place_asset`, `run_script`, `import_tokens` and the kit tools, the ones agents reach for in a batch. `base_rev` holds for every step.
- `group_steps(action, name?)` makes one request of several calls one undo step without packing it into a `batch`: `begin` marks the history (`History::last_serial`) and `end` joins the client's steps above the mark into one named by the group (`group` unnamed), marked as the client's (`History::join_agent_run`, named and marked by `mcp::group`). Each write lands, shows and answers as it would alone, so a later call reads what an earlier made; only the history is joined. The run joined is the client's steps on top of the history: a step of the person's or another client's among them ends it, so only the steps above the latest such step join and the ones under it stay apart (`separate`), and a revert, or a step one took back, ends it too, since joining would hide which step was taken back. A `begin` while a group is open ends that one first; an `end` with none open is refused. A group left open closes at the assistant's turn's end (`Engine::turn_ended`, from the panel), when the client's connection closes (a keyed client's last connection), and on `use_document` of another document; a joined history is written where a tab behind or `serve` keeps it. The agent's `undo` then takes the whole group back.
- `run_script(source, nodes?, layers?, params?)` runs Command Mode's Luau as one undo step marked as the client's, for a loop over many layers in one call (`command-mode.md` §11), `params` filling its header's inputs as `mastik run`'s `--param` does (`command-mode.md` §10); like `batch` it lands whole or not at all, and `base_rev` holds for every layer it wrote.
- `export_png` is the agent's eyes: placement errors no read tool reports (a card under the band below it, a label over a button) show only in the render. A client that can see images is expected to export, look and correct. Its longest side is capped at 1600 by default, and at 1000 for an assistant chat (a keyed call), whose pictures are read again on every later step of its turn (`mcp::CHAT_PNG_MAX`); `max` raises the cap to at most 4096 and is refused above it, since the raster is held in the person's window. A layer, page or region whose raster would still pass `max` pixels at the renderer's floored scale is refused, naming it, rather than drawn (`mcp::png_viewport`). `region: [x, y, w, h]` draws only that rectangle of a page, everything in it, up to 2× as a layer is, so the agent looks closer at one part without exporting it alone; a region with a non-page `id`, or with no area, is refused. `since: rev` draws what the agent's last steps changed (`mcp::diff`): the document as it stood at that revision beside it now, the same rectangle of the same page at the same scale, *before* then *after* (`region` when given, else `id`'s box then and now, else the boxes of the layers added, changed and removed on the person's page, or on the first page anything changed on, 16 units around), with the counts of each and the box. Every look a client keeps (all 1,024 of them) records the step on top of the history and the whole document's fingerprint (`revisions::fingerprint`), so the earlier document is rebuilt by taking back the steps done since, or bringing back the ones undone since (`History::state_at`), and held to that fingerprint: a state the history no longer gives back (an edit merged into a run, a step dropped past the history's length) is refused rather than drawn wrong. A revision the client was never shown is refused; the current one answers `unchanged`. Images are bounded by their pixels, so neither image counts against the answer budget.
- Every read refuses an answer past 100 KB (`mcp::ANSWER_BUDGET`) with its size and the narrower call to make, its `since` answers included: a harness cuts a result past its own limit, and an answer cut mid-way reads as a smaller document or a shorter list. One check in `answer_ids` covers every read (`mcp::read_fits`), the library's lists that need no document included, behind the reads that name a narrower read of their own (`get_document`, `get_node`, `get_outline`, `export_svg`); `run_exports`, `export_prototype` and `export_flow_map` keep their own budget and an image is bounded by its pixels. So every list has a way to ask for less: `find_nodes` and `find_like` a `limit` with `more` counting the rest, `list_components`, `list_variables`, `list_styles`, `list_scripts`, `list_documents` and `list_kits` a `query` on the name, the checks and `export_code` their `ids`. A page is never drawn above 1×, a layer above 2×.
- A write answers `created`, the layers it brought into being and never one that was there before; what else it made, named for what it is (`image`, `variable`, `mode`, `collection`, `style`, `table`, and `property` by the name `set_instance_property` takes), when it made one; `main` from `make_component`, made or turned into one; and `said` when its verb has something to say the document does not show: how many matches `replace_text` wrote and how many it left alone, what `import_svg` left out, how many places `merge_colours` changed, from `add_variant_value` that no variant holds the value yet: `add_variant` copies one and `set_variant_value` gives the copy the value; from `duplicate` of a main, that a main's copy is an instance of it: `add_variant` copies a variant as a new one and `duplicate_as_component` copies a main as a main, since an agent duplicating a variant expects a new variant and gets an instance inside the set; and from `set`, when its `text` holds a `{…}` whose head names a variable or table of the document (`set::reads_as_expression`), that a text shows its braces as written and shows data through a list whose rows are `opened` filling a component's text property, or bound to a string variable (`bind_variable`, field `content`) that an action sets. That write still lands; the note is there because agents write an expression into a text and take it for a binding.
- `find_nodes(query)` is how an agent reaches "the home header" without reading the whole document: layers whose name or text contains the query, each with its id, name, kind, the names of its ancestors, its own box in world space to 0.1 and `selected` when it is or holds a selected layer, so two layers of one name are told apart by where they sit without another read. A request about one part of a page is a find and a subtree read, not a snapshot. `get_outline(id?, depth?, limit?)` is the map before the find: a page's or layer's layers two levels down by default, as a table (`columns` once, then one row of id, name, kind, own box in world space to 0.1 and depth per layer, in paint order with a parent before its children), with `more` counting the rows past `limit`, `selected` the selected layers under it and `origin` where the layer's own (0, 0) lies in world space (a page's is `[0, 0]`), so where a page's sections sit is one call instead of a `list_children` per level. Both boxes leave the stroke out; `get_node`'s `world_bounds` and `get_bounds` take it in. Every box a read gives is `[x, y, w, h]` in world space. `find_like(id, by)` reaches the rest of a kind from one: *Select same* (fill, stroke, font, effect, `app::shares`), *Select matching layers* (`matching::matching_layers`) and a main's or set's instances, over every page.
- Each structure verb refuses where its menu row dims, in that row's words: `frame` where `build::can_frame` refuses, `outline_stroke` without a visible stroke, `divide` without an overlap, `blend_shapes` with `blend::Refusal::says`, `push_to_main` into a kit's or a locked main. `delete_node`, `distribute`, `arrange` and `reset_overrides` refuse, saying why, when they would write nothing, rather than answer success.
- `replace_text` without `nodes` searches every page but drafts, since no page is in view to stand for the person's. `reparent` into the layer's own parent counts its place without it, so with no `index` it goes on top.
- Colours travel as `#rrggbbaa` between the reads and `merge_colours`: `review_colours` writes them, `merge_colours` takes them back. An `into` a variable carries binds the raw paints to that variable, as Colour review's default target does. A merge that would change nothing is refused, saying why: *every place is on a locked layer*, or *every place is that colour already where no variable binds: a text's runs or colour, a gradient stop, a shadow*, a place that takes the value rather than a binding and holds it already being no use (`color_review::Merged::uses`).
- A verb refuses a kit's vendored component (`Document::in_vault`), which a kit instance's `component.main` names: the person can never select one, and an edit there would change every instance until the kit's next update undid it. Reading one is fine, and `create_instance` and `swap_instance` may name it as `main`. `run_script` is held to the same by Command Mode's host, which refuses any commit that would change a vendored layer.
- The canvas chrome a person lines work up against is the agent's too. `set_layout_grids(nodes, grids)` writes frames' whole grid lists as the *Layout grid* card does, a grid given in part completed from a new grid on its `axis` (`loose`'s `grids`), refused on a layer that is not a frame. `set_guides(owner, guides)` writes a frame's or a page's whole guide list: a guide listed with its `id` is kept, moved and recoloured in place, one without is added, an unlisted one is removed, and an id that is none of the owner's guides, or one of another axis, is refused rather than read as a new guide. `set_canvas_colour(page, colour?)` sets the page's ground, opaque, or clears it to the viewer's default as the inspector's reset does. The snapshot reads them back in the shapes these take: a frame's `grids` and `guides`, a page's `guides` and `ground`.
- **The prototype is document fields, and there is no play tool**: an agent checks a prototype by reading what it links. `get_prototype()` answers it whole: each flow with the frames its links reach from its start, as the flow map draws them (`flow_map::plans`), each interaction on them in the flow map's words by its `frame`, `layer` and `layer_name`, and `holds`, what keeps `export_prototype` from running, in that refusal's words. `get_node` answers a layer's `reactions` and `play` and, on a page's id, the page's `flows` and `play`, each absent when empty or at its default (export.md, *Snapshot*). `set` writes them whole through `set_reactions`, `set_play`, `set_flows` and `set_page_play`, a page's `play` going to `set_page_play`. The document's `play_export`, which `get_document` reads, is written whole by `set_play_export`, as the export card keeps it; a flow it names by `{page, flow}` that is no flow is refused listing the flows, and `opens` must be one of `flows` when that is not empty, as the card keeps it. A reaction, action or flow written without its `id` is given one, so a list read and written back keeps its items. An action may be a bare word (`"Back"`) and its kind and a trigger in any case; a transition left out is the page's default for a new link, and one written as its kind alone (`"SmartAnimate"`) or in part is completed from it, except that a smart animate named by its kind without a `direction` takes no side, so its unpaired layers fade. A read leaves out each transition field equal to the page's default but keeps the side of a smart animate whose kind it writes, so what it reads writes back the same (`verbs::reactions_value`, `transition_in`). A key trigger names its key as egui does (`"Left"`, `"Space"`, `"Enter"`, `"A"`). Each action and trigger is settled alone (`verbs::actions_in`), since inside a keyed item serde loses the path a repair needs. Layer ids inside are wire form; a variable, mode, script, table or a row action's column may be given by its name, as a top-level id parameter may, in a reaction, in a flow's starting modes and values and in a layer play's `input.var` (`verbs::reaction_names`, `flow_names`, `play_names`; `insert_subtree`'s tree `play` too), a name that is none refused at its path and an id kept as it is. A name shaped like an id (a mode called `16:9`) is taken as the name when no item holds that id and one is called it, since a nested id may dangle and would otherwise be stored without a word. A flow's `values` also take an object of values by variable name or id (`{"Filter": "Fix"}`), and a value given bare is written as the cell of its variable's kind (`verbs::bare_cell`). An expression (*Set variable*'s `to`, a branch's `when`, a row action's cells and its `FirstWhere` test) may name what it reads, `{Count}`, `{Products.rows}`, `{Products.first.Price}`, `{Products.Price.sum}` or, in a row action, `{row.Price}`, and is stored by id as the Prototype tab's field stores it (`prototype::expr_stored`, through `verbs::exprs_stored`, which `insert_subtree` runs on a tree's reactions too); a read gives it by name as the field shows it (`verbs::exprs_shown`), so an agent can read its own conditions, and what it reads writes back as it was: a name two variables share stays its id, and an expression naming what is gone reads whole in the stored form. One that does not read, names nothing the document has or comes to a kind the field refuses is refused at its path (``at `reactions[0].actions[0].to`: `{Cont} + 1`: …``); one by id naming what is gone is kept, since targets dangle. An *Edit row* with no `cells` is taken, as the Prototype tab makes one, so what an agent reads writes back. The door's refusals are named by path: *Run script* under a trigger no person fires (``at `reactions[1]`: Run script needs a person's act to start it…``), a repeated id, an unusable timing or overlay value, a non-finite scroll trigger point, and a target that is there but would never play (`verbs::targets_checked`): a screen action going to a layer that is no frame, *Change to* switching a layer that is no instance or main or switching to one that is no main; `set_flows` likewise refuses a start that is there but is no frame. A target that is gone is kept. `publish_kit` answers `left_out`, the actions the publish took out of the kit's mains (kits.md, *Publishing*).
- **A layer's annotation** (`Node::note`, `core-model.md`) is written by `set`'s `note`, through the `set_note` verb (trimmed; empty clears it), which a `batch` step may also name; it is in no phase list, so it is no tool of its own. `get_tree` reads it as `note`; the snapshot does not carry it.
- `warp(nodes, preset?, bend?, vertical?, corners?)` is *Warp*'s commit (`mastik_core::warp`): a preset (*Arc*, *Flag*, *Bulge*, *Wave*, *Rise*, *Squeeze*, *Fisheye* or *Twist*) bent by `bend` (−1 to 1), or the selection's world box's corners moved to `corners`, baked into paths; it refuses as the card does (`warp::Refusal::says`), an envelope that turns over itself, and one that moves nothing, and answers the paths that replaced layers that were not paths. `trace_image(node, …)` is *Trace image*'s commit: the picture rendered as shown through the host (`ImageSink::shoot`, the card's own render), traced with the card's settings (`colours` for a colour trace, else black and white at `threshold`; `speck` in units), placed as a *Trace* group just above the picture, the picture kept unless `keep` is false. A caller with no renderer, a script, is refused.
- `repeat` is *Repeat*'s commit (`mastik_core::repeat`): one of a ring's `count` (with `angle`, `turn`, `x`, `y`), `line: {count, gap, down}` or `grid: {cols, rows, gap: [x, y]}`, gaps between boxes, 16 unless given, and `linked`. It refuses as the card does (`repeat::layout_refusal`), and among an auto layout's own items answers the layers and their copies rather than a group.
- `set_selection` takes layers of the page the person is on, never the page itself, and does not switch the page: a selection never spans pages (`Selection::retain_existing`), and the agent does not move the person's view.
- Writes name layers `node` and `nodes`, as their verbs do; the reads, `set_selection` and `make_local` name them `id` and `ids`. The phase lists above give the main parameters, not every one; `tools/list` is the full signature.

#### Revisions

The person and the agent edit one live document, so an agent's earlier read goes stale without its knowing. Each document has a revision that every commit advances, the agent's or the person's, undo and redo included. A refused `batch` or `set` takes back every step it made and puts the revision back where it was (`EditorSession::mark`, `rewind`), so no client is told of a change that is not there. It also gives the person's redo back (`History::take_redo` before the first step, `restore_redo` after), as does a refused Apply of a proposal and a `batch` or `set` that lands nothing: each step's commit clears the redo, and an agent's write that did not land must not cost the person theirs.

- Revisions come from one counter per process, seeded with the launch time in microseconds, so a `rev` from another process (a `serve` before the window took over, the app before a restart) never matches one here and reads as unknown: `since` answers in full and `base_rev` is refused.
- Every tool result carries `rev`. The host remembers, per client, the revision it last showed; when the document moved since, the result also carries `changed`: the layers added, changed and removed since then, by id and name, found by comparing each layer's snapshot entry, so a layer a reflow moved is reported beside the one edited. Each list names at most 50 (`CHANGED_LISTED`); past that, `left_out` counts the rest of each list, names in `in` the top-level layers holding them, since one deleted frame listing every layer in it buried the answer it rode on, and gives in `read_all` the call that lists the rest: `get_document` with `since`, the revision the report runs from, and `brief`, which answers every layer added, changed and removed since by id and name however many (`revisions::since_brief`), and is refused for a revision the client no longer keeps whole rather than answered as nothing changed.
- `get_document`, `get_node` and `list_children` take `since: rev` and answer only for the layers the read covers: the document, the layer (with `subtree`, everything under it), or the parent and its children. `unchanged` when none of those moved, else `get_document` and `get_node` answer the covered layers changed and removed since, and `list_children` its whole list of rows with `since`, since a row is short and a reorder moves the parent rather than a child. Nothing is withheld unless the agent passes `since`: a harness may have summarised its earlier read away.
- A registry verb takes `base_rev`. If a layer it writes changed after that revision the write is refused and the refusal lists them; without `base_rev` it applies. A layer a delete removes counts as one it writes, so deleting a frame is refused when the person changed a layer inside it (`build::subtree_nodes`). A layer's fingerprint (`revisions::layers`) hashes its snapshot entry with its note, and a page root's with the page's settings (flows, play), so `set_note`, `set_flows` and `set_page_play` are held too though the entry lacks those fields. A table is held the same way: each look records a hash per table (`revisions::tables_of`), and a write to a table someone else changed since is refused naming it (*People changed since rev N. Read it again with get_table.*). The client's own writes since are not changes against it, so several writes off one read each pass that read's `rev`; each remembered revision records the layers and tables others added, changed or removed on the way to it. An added one counts, since a name the client read may now resolve to it: a table deleted and made again under its name, or a layer a script finds by a name someone gave a new layer, is refused as changed. The last 8 looks keep every layer's fingerprint, for `since` and `changed`; the last 1,024 keep only those ids, so an agent writing many times off one read is not sent back to read again. The kit tools and `import_tokens` take none.
- **A client** is the key `mastik mcp-proxy --client <key>` (or `MASTIK_MCP_CLIENT`) puts in `initialize`'s `_meta` under `io.github.fadion.mastik/client`, else the connection. A keyed client's document and revisions outlive its connection, so a harness that starts a process per turn finds them on its next connection, with `changed` reporting what the person did in between; the host keeps the 32 most recently used keys. `use_document` of the document a client already uses keeps its history and answers `changed`; the proxy's own restore after a reconnect passes `restore` and answers none, leaving it for the agent's next call. "Never told of its own write" holds per client.

Server-sent notifications would be the protocol's own channel for this, but harnesses do not put them in front of the model mid-turn; a tool result always reaches it.

#### The commit door

Every write goes through the commit door the app's edits use (`EditorSession`), so the same passes run for an agent's transaction: `keep_insets` and `keep_flex_sizes`, the eight `keep_*_bindings` passes, then `propagate::owed`, which runs `style::settle`, `swap::settle`, `propagate_structure`, `component::settle_links`, `variant::settle`, `propagate`, `style::settle` once more, `keep_size_bindings` again and the inert-spacing clear, in that order (pinned by core tests). An agent never has to know a copy exists to keep it in step with its main.

That sequence lives in `EditorSession::commit_inner`, in `mastik-app`, which has no lib target (§15 D786's wall), so `mastik-mcp` cannot call it. It never needs to: the handlers hand transactions to the owning thread, and `serve` is the same `mastik` binary as the window, so both own an `EditorSession` per document and commit through it. The door also reads an edit of a styled layer as an edit of the style while the style browser's *Edit* is open (`style::edit_through`, first in `commit_inner`, §15 D1063). An agent's transaction skips that step: the same call does the same thing whatever is open on screen, and an agent changes a style with `set_style_value`.

#### Phase 3: verbs, not ops

Phase 3 names verbs because the raw ops are refused or wrong alone:

- Binding a field writes a canonical literal beside the binding (`build::bind_*_ops`: 0 for a number, empty for a string, `true` for a visibility), so a main and a copy bound to one variable compare equal whatever either held. A colour binding replaces the paint's brush outright, keeping its alpha percentage (`BrushSource::Bound`, `build::bind_brush_at_all`).
- Removing a variable or style detaches its users to what they drew in the same transaction (`variable::remove_ops`, `style::remove_ops`); removing a mode returns its frames to *Inherit* for its collection (`variable::remove_mode_ops`). Each is refused at the commit otherwise (§15 D1038). A bare `RemoveStyle` or a bare `SetCornerVars` over a non-canonical literal would be refused or wrong.
- Renaming a mode keeps every kit column it reads (`variable::rename_mode_ops`); a bare `SetModeName` re-maps a kit by the new name.
- Making an instance writes a linked copy (§15 D978).
- `bind_variable`'s `field` names any bindable field: corner radii, gaps and padding, width and height, a layout item's min/max width and height, visibility, opacity, a text's content, family, size, weight, line height, letter spacing and paragraph spacing, a fill's or stroke's colour, a stroke's width, and a shadow's X, Y, blur and spread or a layer or background blur's radius; all corners and a set of gaps and padding also read by word (*Conventions*). An effect's colour and a filter's numbers bind nothing. It is one tool over the six `Set*Vars` ops plus the bindings a fill, stroke, effect and layout item carry in their own items (`BrushSource`, `LayoutItem::limit_vars`); an absent `variable` detaches to the value drawn. An item's binding names its item: the core verbs take a stroke's or effect's `ItemId`, and a paint's colour its index in the list.

#### Reads must grow with Phase 3

A bound field's stored literal is a placeholder, so the snapshot reports the **drawn** value of every bound field. It does that for a paint's colour, a stroke's width, an effect's numbers, size and corners (through `Resolved`'s used kind), visibility, opacity, a text's content and family, and a layout's gaps, padding, flow and limits. Beside the drawn values each node names what it reads, in the terms the Phase 3 tools take: `bindings` lists each bound field as `bind_variable`'s `field` with its variable, `styles` the style per slot by `apply_style`'s slot names, `modes` the modes a frame sets, and `component` its part (main, set, instance with the main it shows, or copy with the layer it is linked to), a variant's values, an instance's `properties` (each value as `set_instance_property` takes it, and whether it differs from the main's) and an instance's or copy's `overrides` (the fields `reset_overrides` would put back, `"fills"`, `"geometry.size"`, `"swap"`, from `reset::overrides`). The fill, stroke and effect lists stay visible entries only, so each carries its item id and a fill or stroke its index in the whole list. A text reads back as written too: `paragraph` and `block` in the shapes `set_paragraph_style` and `set_block_style` take, and `runs` and `paragraphs` as `style_text`'s and `style_paragraphs`' arguments, counted in characters, so a run's colour and a list item's marker and level are there; a family a run sets that the host lacks warns as the default's does. Where layout draws a node otherwise than authored, `specified` carries its stored transform and geometry beside the used ones. The snapshot is what is drawn, which a whole-list write cannot be built from: `get_tree(id)` answers the model instead, in `insert_subtree`'s `Tree` shape (`verbs::tree`), with every fill and stroke including the hidden ones, a gradient's and an image's framing, a stroke's align, dash, cap and join, the effects and exports, a text's runs and a mask's mode, each field only where it differs from a new layer's and no item ids. The tree is a faithful round trip: what it reads inserts back as what it was, so an agent that copies a part and changes it keeps what the part reads and is. It carries the applied `styles`, a frame's `modes` and width `queries`, the `pivot`, `element` and `link`, a frame's `grids` and its own `guides`, the stored `fill_rule`, `fill_hidden_in_export` and `proportions_locked`, and the layer's part in a component: `component` on a main, `copy_of` on a linked copy (an instance's root and every layer inside it, a nested copy's too), `swap`, a set's `set`, a variant's `variant` values and its layers' recorded `lineage` keys, the `props` a main or set defines, a main's `description` and `doc_link`, and a layer's `note`. It carries a layer's prototype `reactions` and `play` in the short forms `set` takes them (`verbs::put_prototype`, written after the tree's own short forms so they never reach them), each transition written whole since the tree may go onto a page whose default differs, a copy's even where they are its main's or empty, since `insert_subtree` fills no copy's reactions from its main; a layer a reaction or a scroll effect targets keeps its `id`, and `insert_subtree` reads the reactions as `set_reactions` does, a transition left out being the default of the page the tree goes into, the door's refusals named under `reactions`, each target inside the tree, a scroll effect's frame too, moved to the layer the tree makes (`verbs::tree_reactions`, `LayerPlay::map_layers`). Bound fields are the model's: a binding a fill, stroke, effect, layout item or flex carries travels in it, and the layer's own (corners, gaps and padding, size, a text's content, family and type numbers, visibility, opacity) are listed in `bindings` as the snapshot names them, beside the placeholder literal their binding draws over (`verbs::own_bindings`, `binding_ops`). `insert_subtree` mints every layer's id first (`mint_tree`), so a reference inside the tree (`copy_of`, `swap`, `lineage`, a property's `bound` and `preferred`) is remapped to the layer the tree makes, which is why a layer keeps its read `id` exactly where another layer of the tree refers to it; a reference outside the tree keeps the document's layer, so an instance read alone inserts as another instance of its main, and a main and its instance read together insert as a new main and an instance of it. A layer whose `copy_of` names a document layer no layer of the tree was read as takes everything it leaves out from that layer, its `kind` too and its `children` as copies of that layer's when it gives none (`verbs::expand_copies`, after `like`); a `kind` it gives of the same variant is completed field by field (a text's style too, but not the main's runs when it gives its own `content`), so a copy writing only a label's words keeps its main's sizing and type; so an agent places an instance by its main and its overrides; a copy falling back to a new layer's defaults would draw with no display, fills or text colour, silently. Its `transform` it takes only as a copy of a child of the main its parent copy is a copy of; a copy at the tree's top, or one whose source is a layer elsewhere (an icon swapped in from another frame), lands where a new layer does, at the identity, since its source's place in another frame would put it outside its own parent's clip. So a copy's field that sits at a new layer's default where its source's does not is an override, and `full_tree` writes it (`verbs::copy_defaults`): every layer field its source's read has and its own leaves out, as that default (an empty list, `false`, `null` for no `display`, `pivot`, `element` or `swap`), and every field of its kind and its text style likewise (`explicit_kind`: square corners, no arc, an upright label as `"italic": false`, an Original case, a zero spacing in px), since leaving it out would now mean "take the main's". A copy's kind written in any case or a frame as `Frame` is completed as its main's variant, and its `corner_radius`, the name `set` takes, is its own corners whether it gives its kind or leaves it to the main. The component ops (a main, a link, a swap, a set and its properties) come after every layer's own, since they are checked once all are there. A layer read from inside an instance whose root the tree does not hold drops its `copy_of`, as a layer pasted out of an instance does, and is placed as a plain copy. Ids name this document's variables, styles, modes and mains: a tree inserted into another document is refused where one of them is missing. A `like` sample is read as drawn instead (`full_tree`'s `drawn`), its look being what a new layer takes. Layout reads back as written: `display`, `item` and `insets` carry the shapes `set_display`, `set_layout_item` and `set_insets` take, so an agent edits one by changing the field it read; the item is the authored one, not the width a frame with width queries is laid at. `list_variables` returns every mode's cells (aliases unresolved and resolved) in the short forms `set_variable_value` takes, and a kit variable's `kit`: the kit's id and name, its kit collection's name when the kit has several, that collection's modes, the document collection it is read from (`read_from`), the kit mode each of that collection's modes reads (`mapped`) and the one read where no frame sets a mode (`default`); `list_styles` returns each style's slot, name, value (in the short forms) and users' count. `list_components`, `list_variables` and `list_styles` also carry each main's or set's, variable's and style's description (`Node::description`, `Variable::description`, `Style::description`), read from the model, and `list_components` each main's or set's documentation link (`Node::doc_link`); the snapshot carries neither. `list_components` gives a set its `variant_properties` (each `name`, `values` and, where tied, `states`), which name what each variant's `variant` list holds.

#### Phase 4: building and using a design system

An agent builds a design system by filling a document through Phases 2 and 3 with mains, variables and styles, then `make_kit` and `publish_kit`; it uses one by listing the library's kits, reading a kit's published mains, variables and styles with `get_kit`, placing a main with `insert_from_kit`, and taking later publishes with `accept_kit_updates`. The tools are the app's verbs:

| Tool | Backing |
| --- | --- |
| `insert_from_kit` | `kit::insert`: vendors the main and every nested main it reaches into the vault; variables and styles carried by `tokens::plan` into the document's own tables |
| `accept_kit_updates` | The app's accept, per kit or all kits, never per main; transaction built by `kit::update_all` |
| `make_local` | `kit::make_local`, forking the kit variables and styles the main reads |
| `map_kit_modes` | The variables browser's mapping row (`panels/variables.rs`): a `SetKitModes` carrying the kit's held record with only its hand-set `map` changed; an entry from a collection the kit's collection does not read is refused |
| `swap_instance` | Takes a kit main too, vendoring it first (`kit::swap_offers`, `kit::vendored`) |

The raw kit ops (`OpenVault`, `CloseVault`, `SetOrigin`, a `SetKitModes` rewriting the kit's name or modes, `SetStyleOrigin`, whole-variable `SetVariable`) stay behind those verbs, where the planner keeps them consistent.

**Outside undo.** The kit mark is document metadata, not an operation (§5.11a), so `make_kit`, `publish_kit` and `stop_sharing_kit` save the file and `undo()` reverts none (`make_kit` mints the document id first when it has none). They act as the menu's rows do: `make_kit` refuses a kit already sharing and turns a stopped one's sharing on again, `stop_sharing_kit` refuses a document that is not a sharing kit (the refusals live in `mark_kit` / `unmark_kit`, which the palette's rows read too), and `publish_kit` refuses at no change since the last version, as the *Publish* button is disabled then. A save that fails says where the change is: waiting in the window's tab for the person's next save, or dropped by `serve`. `publish_kit` is the only outward write: it changes what every consuming document is offered (an open one's update pill within the watch's 45 seconds or on regaining focus; a closed one's when next opened).

**No dialog (§15 D1097).** The agent publishes, stops sharing and files documents on request: the request is the person's ask, the publish note is the tool's argument, and a dialog would hang the agent on a window it cannot see. The person instead gets the status line saying the agent did it: the app's own line for the act (`kits::made_kit_said`, `stopped_sharing_said`, `publish::published_said`), or *Filed Landing* for a new document, followed by *· by* and the name the client gave at `initialize` (*Published Atlas v4 · 3 components · by Claude Code*). The window puts it on its status line whichever tab the document is in; `serve` logs it.

**Documents by path (§8.1).** `create_document` files a new document in the library (`library::store::file_document`) and returns its path, which the agent passes to `use_document`; opening it never changes the tab in front of the person. Renaming, moving, duplicating and trashing documents stay with the person on the dashboard.

**Any document, either host (`mcp::kits`).** The app's kit actions are `MastikApp` methods on the tab in front, but an agent's document may be a tab behind or a `serve` session. So Phase 4 runs on that document's session and the library the host lends (`Documents::with_library`, a scan read again for each call), through the core verbs the app's own run on (`kit::insert` by way of `kits::picker::build_placement`, `update_all`, `make_local_report`, `publish`) and the app's functions that read a library (`kits::index::kits_in`, `kits::updates::waiting`) or set the kit mark on a session (`kits::mark_kit`, `unmark_kit`, `publish::publish_in`, which the `MastikApp` methods call too). A kit's published state is read from its file at each call, with the version that file says it published (§15 D1023), never from the window's `KitShelf`. The mark's changes are written at once (`Documents::save`): the person's own save for the tab in front, a direct write for a tab behind or in `serve`. `list_documents`, `list_kits` and `create_document` need no current document. A kit is named by its id or its name; `insert_from_kit`'s `x` and `y` are the left and top of the instance's box in its parent, as `create_instance`'s are (`build::cornered_at`), and an edge not given stays at its main's own place.

#### The assets browser (`mcp::assets`)

`search_assets` and `place_asset` are the assets browser (`app-canvas-chrome.md`, *Assets browser*) for an agent.

- **Only what the person switched on answers:** the icon sets on in Settings › Assets, the kit icon packs on there (`sets::icon_packs`, the current document's own kit left out) and the photo services on. An agent never switches one on, since that reaches the network; the refusal says the person does it in Settings › Assets.
- **`search_assets`** is a read (`LATER_READS`). Each query is its own search, 12 icons or 6 photos unless `limit` says, at most 30. Icons are ranked by the panel's `panel::find_icons` and answer `asset` (`icon:<set key>/<name>/<variant label>`, or `kit:<kit id>/<main id>`), name, set, variant, `size` (the variant's grid), aliases, licence, and `credit_required` when it is CC BY. Photos come from the service's first page and answer `asset` (`photo:<service>/<id>`), alt text (the service's title), credit sentence, licence and pixel size, each with a JPEG thumbnail at most 160 px as image content after a text naming its asset id; thumbnails stop at 64 KB an answer, said in `said`. A photo query of several words that finds nothing carries a `note` that one or two words find more, since the services match every word. A photo search asks one service: `source`, else the panel's, else the first switched on (`service_of`). A service's refusal (its hourly limit, a missing or refused key, no connection) is said as the panel's empty state says it and names the other services switched on as `source` values to try. A call takes at most 8 photo queries. An agent's photo searches are kept 10 minutes, apart from the panel's, since the service's hourly limit is the person's; a new search forgets the oldest landed ones past 32 (a pending one is never forgotten, or the call waiting on it would ask again). A refusal is answered once, and every refusal remembered is forgotten with it, so a key added or a connection back is used for each query at the next call. `place_asset` finds a photo only there, so one from an expired search is refused with *search again*.
- **`place_asset`** is the panel's insert. An icon lands as *Insert icon*: the SVG importer's group named after the icon, `size` points across (the variant's grid unless given), its box's corner at `x`, `y` in `parent`, `currentColor` drawn in `colour` (`"#rrggbb"` or `"#rrggbbaa"`) or black as the panel draws it, so an agent never recolours an icon's nested strokes afterwards, with `panel::icon_credit`. A `colour` naming a colour variable by id or name draws the icon black and binds every solid black fill and stroke of it to the variable on landing, each keeping its alpha (`assets::icon_variable`, `put_icon`), so a placed icon reads the document's tokens rather than raw paint `review` would ask to merge; a name that is no variable, a variable that is no colour, or anything else is refused. A `colour` on a kit icon or a photo is refused rather than ignored. A kit icon goes through `insert_from_kit`, an instance at its component's size. A photo downloads at Settings' *Photo size* (one that cannot is refused with the source's HTTP status, or as a failed connection or a file past the 64 MB cap), then lands as *Insert photo*, an image rect with its box's corner at `x`, `y`, `size` its width at its aspect, else its own size fitted to a frame parent as a drop is; or, with `fill`, as one *Fill with photo* step on every layer listed, held to the panel's rules (`panel::fillable`, `panel::fill_tx`: unlocked shapes or frames, not text, lines, spirals, arcs or parts of an icon) before any download. A `parent` or `fill` layer in a kit's vendored component is refused as every write tool refuses one (`writes::refuse_kit_vault`), before any download and again when the asset is laid down. Every placement carries its credit, and an Unsplash photo is reported to its `download_location` after the commit (`Assets::report_download`). The step takes the panel's name and glyph (`EditorSession::name_mcp_step_as`), still `Origin::Mcp` with the tool `place_asset`.
- **A call that waits on the network does not block its host.** One that needs a set still loading, a search, thumbnails or a download is kept (`Engine::handle_or_wait`, a `Call::again` sharing its claim and reply), and `drain_mcp` runs the waiting calls again (`Engine::run_later`) when the assets workers land something (`Assets::landed_count`) or every 0.5 s, each run through the whole engine path (access, short ids, revisions). A placement still downloading after 25 s (`mcp::assets::WAIT`, inside the queue's 30 s) answers `{pending: "p<n>"}` and keeps running; `place_asset({pending})` answers what it made, once, or that it still downloads, the last 16 finished kept. A search past 25 s is answered as not done.
- **Either host.** Each lends them what they read (`Documents::desk`). The window lends its own: the preferences, the assets workers, the keys Settings read, and the kit packs its `KitShelf` reads. `serve` lends the same from the saved preferences as they stood when it started (a window that starts takes over, so they cannot change under it): its own assets workers, the same network calls as the window's; no keys read ahead, so each worker reads its service's key from the keychain, as the window's do before its own read lands; and each switched-on kit pack read from its file on its own thread, as its kit tools read kits, kept until the file changes. It runs a waiting call again as `drain_mcp` does, polling every 50 ms while one waits, and does not hand over to a window until none waits, since its answer would go with the process.
- **Chats.** `search_assets` runs at every level; `place_asset` runs at Edit, and at Propose is a call in `propose_edit`. The placement is split in two: `assets::hold` does what needs the host's assets browser (the switched-on check, the set, the search, the download, the credit) and `assets::put_held` lays the asset down on a session. A proposal holds each placement's asset from when it is proposed (`Proposal::held`), so the proposing call waits on the download as a placement does (past `WAIT` it is refused, the download going on, so asking again finds it), the check and the apply lay it down with no network, and a search expiring in between does not matter. The photo is reported to Unsplash when the person applies it, since only then is it used. The held assets are kept in memory only, a photo's pixels being too large for the saved thread: a proposal read back from one refuses its placement and asks for the proposal again. A kit's icon is an instance its kit tool places, so it is placed at Edit only.

#### Exports

`set_exports` writes a layer's export list (the *Export* card's rows: format, scale, prefix and suffix, background, quality, trim, square padding; `ExportSpec`, see export.md §7). `run_exports` renders the listed layers' files through `mastik_export::plan` and `plan::render` (the path `mastik export --all` takes) and **returns bytes with their names** rather than writing them, each file an embedded resource. Every file answer travels so (`Content::File`): a text type (`text/*`, SVG, JSON, JavaScript: `wire::is_text`) of at most 256 KB (`wire::TEXT_INLINE`) as text, anything else or larger as a base64 blob, since a client reads a text resource into the agent's context, which `export_prototype`'s megabytes of HTML overflow, and saves a blob as a file. Where files land is the client's and the person's call. Every file is drawn on the person's UI thread, so a raster past 64 megapixels (8192²) is refused before anything is drawn, naming the file and the layer, and an answer whose files pass 16 MB is refused, pointing at `ids` and `export_png`. A *One file per row* setting's files each say their `row`, and `rows: {from, count}` (from 1) keeps such a setting to those rows, other settings unaffected; a row's files passing the budget are refused naming the run that fits (*24 files pass 16 MB: ask for `rows: {"from": 1, "count": 9}`, then the rest*). A row's pictures beside a linked table are read as the export worker reads them (`panels::with_row_pictures`). With no `ids` it takes the layers *Export all* takes (`panels::exportable_layers_of`); the CLI keeps its own copy of that walk, held to the same answer by `build::all_in_document_order`.

`export_code` writes layers as HTML/CSS, React or Vue through `code::Target::export` (export.md, *Code export*), the CLI's `--html`, `--react` and `--vue` path, and returns the files with the three report lists (`approximated`, `positioned`, `inlined`) beside them, never writing to disk. `ids` defaults to the selection, as *Export as HTML / React / Vue…* takes it, and with nothing selected (always, in `serve`) to the layers of the person's page, the first page's in `serve` as the CLI takes them. It is the door the deterministic translation exists for: the snapshot carries used values, so CSS an agent writes from it is absolute positions, where `export_code` keeps the specified layout, the variables and the components for the agent to build on.

`export_prototype` and `export_flow_map` are the prototype export card's *HTML file* and *Flow map* (prototyping-player.md, *Exports from the player*), answered the same way: one embedded file under the name the card offers (`‹document› — ‹flow›.html`, `‹document› — Flow map.pdf`), refused past the same 16 MB. The HTML file is `prototype_export::html`, the card's packer, under the document's own export settings (`Document::play_export`: the flows, the one it opens on, device frame, bar, hotspot hints, scaling, *On a phone*), which the report repeats as `settings`, beside `flows`, each flow that goes in as *Page · Flow* (`prototype_export::flows_in`), since the file's name names only the flow it opens on; they are changed for every later export with `set_play_export`, the card's way, not per call. Like the card it is refused while `prototype::holds` lists an interaction, each named by its layer, and it needs the browser player `player_build` finds, so a host without one refuses, naming where it looked. The flow map takes every flow, as the CLI's does, and reports `approximated`. Each is checked on the owning thread (no flow, an interaction holding it) and refused there at once; the file is packed from a copy of the document on a worker (`reads::export_work`), as the card packs it, while the call waits among the asset calls (`Engine::later`, run again at least every half second) without their time limit, and is answered on its own reply when the worker is done, so packing the player never holds the person's frame. Neither is a step `batch` or `propose_edit` runs, so this is their one way in.

#### Checks, tokens, fonts and versions

- `check_contrast` is `mastik_export::contrast::check_with`, the check *Check contrast* and `mastik check contrast` run, on the host's thread with the faces the canvas uses; `ids` narrows it to the subjects under them. It counts what it measured and what fails, and lists the failing findings only unless `all` asks for every one. `fix_contrast` is its fix. `review_colours` is *Colour review*'s census and groups (`color_review`).
- `design_context` answers what a frame, group or page already uses, so an agent adding to it matches it without reading every tree: the distinct text styles (each layer's default style with its ink and, below 1, its layer's opacity, which `like` takes from the sample; a sample per style), the colours seen in fills, strokes and text, corner radii, shadows and blurs, families, the bound variables' and styles' names, the sections (the root's shown children and their world boxes), the content column, the gaps and the controls. The column is the most common rounded left and right edge of what the sections hold, a child spanning its section's width being a background and left out. `gaps` are the empty bands at least 24 high between sections taken top to bottom, each named by the sections above and below it with its world top and height, so "between the navigation and the logos" is a lookup. `controls` are the small control-like layers, up to six, most repeated first: a frame or group no larger than 480 × 120 holding one text and at most two other layers, painted by itself or by a shape covering it, the text inside and centred down that ground, a button or a field. Alike ones are counted together by size, radius, fill, stroke and the label's family, size, weight and colour, and each kind gives a sample of the layer, its ground and its label. The root carries its `origin`, where its own (0, 0) lies in world space, as `get_outline`'s answer carries its layer's: the writes place a child in its parent's own space, which is the world box less the origin. A text style's sample and a control's ground and label are the layers to name in `insert_subtree`'s `like`. Only what is seen counts: hidden layers and paints, masks and image fills are left out, and lists stop at 24 with a count of the rest. A page holding one frame is read as that frame, the usual shape of a web page. Its boxes leave the stroke out, as `get_outline`'s do, so a box's left and top less the origin is what `set`'s `at` takes. It and `check_layout` are `mastik_export::context` (in `mastik-export` for `snapshot::bindings`); the app's handler, `mcp/context.rs`, only reads their arguments.
- `check_layout` lints placement from what the session has laid out, without a render: text cut at its box or line limit (`TextLayout::truncated`) and lines whose baselines leave a fixed box; a layer partly or wholly outside the frame that clips it, except a plain vector shape partly cut, which is how a frame crops a decoration (a text, a frame, a group or a picture still counts); a flex or grid child past its frame's box; a shown layer with no width or height (`zero_size`), except a line, an arc or a spiral, and a box flat on one side that a stroke draws as a line: one visible, inking and not inside-aligned, on a long side (all sides, or the top or bottom of a flat height, the left or right of a flat width); a text is never spared, since its stroke outlines glyphs; a shape, empty frame or empty group with no visible fill, stroke or effect (`draws_nothing`; text, booleans and their operands (a group operand's members too), whose shape the boolean paints, slices and an empty box a flex or grid frame lays out, a spacer, are not); two unrotated texts whose boxes share more than a sliver; between siblings, a text a filled layer painted above it covers (`text_covered`) and a text that runs out of the nearest filled layer under it holding its centre (`text_spill`, a label leaving its button); and characters no face of a text's runs has, which draw as `.notdef` boxes (`missing_glyph`, naming them). Edges get one unit of slack, so a hairline stroke on a frame's edge is not a finding; a box of no height or width, an unstroked line's, is inside a clip it lies within; and a layer found clipped or overflowing answers for its descendants. A cover from outside the text's own parent is not checked. Overlapping shapes, text over a busy ground and spacing rhythm are `review`'s, since they are often meant or need a render: `check_layout` answers what is wrong, `review` what is likely unintended.
- `review(ids?, page?, step?, level?)` runs the design checks past `check_layout` (`mastik_export::review`, one function a check over a `Scope` of the shown layers under the roots), each finding with its code, layers, line and, where one fits, what to use `instead`, at most 100 with `more`: `overlap` (two siblings that are not text whose boxes share more than a sliver, neither holding the other, a boolean's operands, a group operand's members too, passed over); `busy_ground` (a text whose box, drawn without it at most 240 px across, has a tenth or more of its pixels changing sharply from their neighbours, as a photograph or a pattern does and a gradient does not; at most 150 texts drawn); `rhythm` (between layers placed by hand in one column or row, a gap within 4 units or a quarter of the others' median but not it; a boolean's operands, a group operand's members too, are its shape and passed over) and `off_scale` (a flex or grid gap or padding not bound to a variable, or a hand-placed gap, off a multiple of `step`, 4 unless given); `raw_value` (a solid fill or stroke, an even corner radius, or a gap or padding equal to a variable of the document's own that may bind it, in the mode in force at the layer, written raw; for a radius or a gap the variable offered is, of those, the one scoped to the field, then one whose name names it, a word of it starting with `radius`, `radii`, `corner` or `round`, or with `space`, `spacing`, `gap`, `padding`, `gutter` or `inset` (`rounded/md`, `spacer`; never mid-word, so `background` names no corner), then any, since an unscoped number binds every number field, but never an unscoped one whose name names only the other field (a `radius/*` for a gap, a `space/*` for a corner), whose value matching is a coincidence, a scope admitting both fields, as a token import writes, counting as none: `review::fitting`; a fill's or stroke's `instead` adds that `merge_colours` with the colour as both `colours` and `into` binds every raw use at once where that merge can, the variable being the one of its colour that paints on any page already use, since the merge finds its target among the colours in use; the others' says to bind the variable) and `raw_style` (a fill, stroke or effect list, or a text's whole type but its colour and language, equal to a style's, not applied), each gathered per variable or style, a colour per variable and raw colour, since a variable matches another colour in another mode; `near_duplicate_colours` (Colour review's groups at *Close*, `merge_colours`' input, each only where a merge into its default target would change something, a use or a locked place, so a raw colour that is a variable's exactly on places no variable binds is none; its layers are the raw members' but the target's, never ones already bound to it, and a bound member is named by its variable, ``#0b1020 (`Ground`)``); `radius` (an even radius within 2 units or a fifth of one more layers use); `low_contrast` (`contrast::check_with` on the texts, the contrast check's own measure); and `dangling_target` (a layer whose reactions, scroll effect or input name a layer, variable, script, mode, table or column that is gone, one finding naming each kind, copies said at their main; a page flow whose start is gone, on its page; a report, never a refusal, since targets dangle by design: `prototyping-model.md`). `mastik check review <file> [--page]` runs the same checks. Each check is a public function of its own; `health` reads `near_duplicate_colours` and `spacing`'s `off_scale` gaps, and the private `raw_matches` that `raw_values` is built on, for every matched layer rather than a finding's capped names.
- `health(ids?, page?, pages?, step?)` answers *System health*'s readings (`review::health`, `Health::to_json`; `app-canvas-chrome.md`, *System health*) over `ids`, else the page, else with `pages` every page but drafts (`review::every_page`): `bound` (paint, type and spacing, each bound against all, and the overall percentage, rounded down), then `raw_match`, `near_duplicates`, `off_scale`, `detached`, `dangling` and `unused.components`, each a count with at most 100 layer ids, and `unused.variables` and `unused.styles` by name, document-wide whatever the scope. The card, this tool and `mastik check health` read the one function, so their numbers agree.
- `export_tokens` and `import_tokens` are the DTCG file the *Export tokens* and *Import tokens* doors read and write, as text: the agent hands the file over and takes it back, and nothing is written to disk or linked. An import applies every row the review starts ticked (`dtcg_in::Review`), removals only with `removals`, as one undo step named by the tool. Tokens the file puts in no collection land in `collection`, an existing collection's name (the first when absent); one the document lacks is refused listing the collections there are (`tokens_import::one_shot`). A family the import's type styles newly bring that the host's font list lacks (`Documents::fonts`, what `list_fonts` answers) is named in `said`, since text set in it draws in a fallback without a word.
- `list_fonts` answers the families the host can set text in: the window's font service (installed, and web fonts it fetches on first use), `serve`'s installed families (`mcp::system_fonts`). `replace_font` is the one tool held to that list, called alone, as a `batch` step or as a `propose_edit` call: its `to` must be a family `list_fonts` answers, written in the host's spelling, and not the family it replaces, since a replacement drops each match's axis and feature settings. A family an agent names is loaded as one the person picked: the window loads the tab in front's families after an agent's commit, a tab behind's when it comes to the front, and `serve` registers the installed faces of each family its document names on opening it and after each commit, then lays the text out again.
- `save_version(name?)` saves the document and pins it (`library::store::pin_version`), as *Save named version…* does, for a library document only; `undo` does not revert it. `list_versions` reads them back, and `compare_version(version)` answers what changed since one, named by its `at` or its name: `mastik_core::diff` of the version against the document now, as *Compare with now* reads it, with each value before and after, refused past the read budget. Restoring one stays with the person, in *Version history*.

#### set_pivot

`set_pivot` is for the person who comes after the agent. An agent can already rotate about any point with `set_transform` and an affine it computes, since the pivot is baked by the gesture that reads it and never composed into the world transform (§15 D55). The stored pivot decides where a person's later turn goes (canvas rotation, the inspector's rotation and skew fields, a flip; resize and skew drag ignore it, §15 D60): a needle about its hub, a door about its hinge.

#### Not exposed, on purpose

The fill rule and the proportions lock (visual only, irrelevant to an agent; §15 D1095, D1096). Paragraph spans travel inside `style_paragraphs`. Restoring a version, which replaces the document outside undo, and linking a tokens or chart data file, which watches a path on the person's disk: both stay with the person. A prototype's video: it replays a take, which only the person records by playing in the window and which lives only while the player is open, and it is written frame by frame to a file over seconds to minutes, past what one answer carries.

## Traps

- **The five list paragraphs of §8.4 are parsed by a test.** `mastik-mcp/src/tools.rs` holds the same names as `PHASE_1` to `PHASE_4` and `CORE`, and `the_tool_list_here_is_the_one_the_design_specifies` `include_str!`s this file and diffs each list in order. The parser finds the `### 8.4 Tools` heading, anchors on each paragraph's opening sentence (*Phase 1 — …* to *Phase 4 — …*, then *Core — listed by default:*), takes the paragraph up to the first blank line, and reads **every backticked token in it as a tool name**, dropping any signature at the `(`. Do not reword the heading or an opening sentence, do not merge a list paragraph into the next, and do not put a backticked aside inside one; put asides after the core list. A rename fails at the comparison, a moved heading fails loudly at the parse. Moving this file means moving the `include_str!` path with it.
- Phase 3 tools wrap verbs; writing the raw op (`RemoveStyle`, `SetCornerVars`) hands the commit a transaction it refuses or a non-canonical literal.
- Kit actions, `save_version` and document creation are not `Transaction`s: they bypass history, so `undo()` is not a safety net for them.
- **`place_asset` asks whether it waits before the call reads the document.** `assets::waits` runs in `Engine::handle_now` ahead of the client's `changed` catch-up, so a call kept for later has reported nothing as seen and its eventual answer carries what the person did meanwhile. Moved below the catch-up, the waiting run swallows that `changed`; no test pins the order.
- A write applied to the `Document` anywhere but `EditorSession::commit` skips the `keep_*` passes and the propagation, and every gate stays green.
